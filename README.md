## Начало работы

Примите приглашение в закрытый репозиторий под своим аккаунтом GitHub.
Для клонирования понадобится Git и доступ к репозиторию.

До первого HTTPS-клонирования настройте авторизацию локального Git.
Доступ через плагин GitHub не авторизует Git на вашем компьютере.
Если авторизация Git уже работает через Git Credential Manager или SSH,
сохраните существующую настройку; для SSH используйте SSH-адрес репозитория.

Для настройки через GitHub CLI установите [GitHub CLI](https://cli.github.com/),
если команда `gh` отсутствует, и откройте новый терминал. Затем выполните
в своём терминале (Windows PowerShell, macOS или Linux):

```sh
gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git --hostname github.com
gh auth status --hostname github.com
git ls-remote https://github.com/skyzixss/AI-Hackathon-2026.git HEAD
```

Завершите вход в браузере под своим аккаунтом с доступом к репозиторию.
`git ls-remote` должен вывести хеш и `HEAD`; эта команда проверяет чтение
репозитория и не создаёт рабочую копию. После успешной проверки клонируйте:

```sh
git clone https://github.com/skyzixss/AI-Hackathon-2026.git
cd AI-Hackathon-2026
git status
```

Если появилась ошибка `could not read Username`, выполните настройку выше
вручную в интерактивном терминале и повторите проверку. При `Repository not found`
или отказе в доступе проверьте аккаунт в `gh auth status` и принятие приглашения.
Если активен другой уже добавленный аккаунт, выберите нужный через `gh auth switch`.
Команды авторизации: [gh auth login](https://cli.github.com/manual/gh_auth_login)
и [gh auth setup-git](https://cli.github.com/manual/gh_auth_setup-git).

Если папка уже клонирована, используйте её. Прочитайте [AGENTS.md](AGENTS.md)
до запуска ИИ-ассистента. Редактор можно открыть командой `code .`, если VS Code
и его команда `code` доступны.

**Запуск приложения пока отсутствует:** нет исходного кода, манифестов
зависимостей, серверов и тестового набора. Команды вроде `npm install`,
`npm run dev` или запуска Python-сервиса сейчас не применимы.

## Подготовленное окружение

На Mac владельца доступны Node.js 24 LTS и Python 3.14.7. Существующие `.nvmrc`,
`.python-version` и настройки Python в `.vscode/` сохранены как файлы подготовки;
они **не означают выбор стека продукта**. На других компьютерах инструменты
и их доступность нужно проверить отдельно.

Если команда выберет Python, согласуйте его версию с зависимостями. При уже
установленном uv окружение для указанной сейчас версии можно создать так:

```sh
uv venv --python 3.14.7 .venv
source .venv/bin/activate
```

uv может скачать интерпретатор, если нужной версии нет. Это необязательная
подготовка, сейчас выполнять её повторно не требуется. На Mac владельца `.venv`
уже создано и исключено из Git. Команда активации выше предназначена для macOS/Linux.
Docker, БД и библиотеки приложения пока не требуются.

## Ветки и Pull Request

Одна задача → короткая ветка → небольшой PR → проверка другим участником →
squash merge в `main` после разрешения на объединение → удаление ветки.
Автоматическое объединение без явного поручения не включаем. Цель — несколько часов работы,
обычно не дольше одного дня на ветку.

Если защита `main` не настроена или недоступна на текущем тарифе, соблюдайте
этот порядок вручную: не отправляйте изменения напрямую в `main`, а перед
merge убедитесь, что другой участник проверил последнюю версию PR и оставил
одобрение на GitHub. После новых изменений повторно запросите проверку.

Имена веток: `<type>/<owner>-<task>`, например `docs/artem-product-brief`,
`chore/skyzixss-repo-rules`, `docs/pupsik-api-questions`.
Типы: `feat`, `fix`, `docs`, `chore`, `test`. Примеры не назначают задачи заранее.

Начинайте с чистого рабочего дерева:

```sh
git switch main
git pull --ff-only origin main
git switch -c docs/yourname-task
```

После изменений проверьте diff и добавьте только файлы своей задачи:

```sh
git diff --check
git diff
git add <файлы-задачи>
git diff --cached
git diff --cached --check
git commit -m "docs: describe agreed requirements"
```

`<файлы-задачи>` — заполнитель, замените его реальными путями.
Push и открытие PR выполняются после подтверждения пользователя:

```sh
git push -u origin HEAD
gh pr create --base main
```

Команда `gh` требует установленного и авторизованного GitHub CLI;
PR также можно открыть через сайт GitHub после отправки ветки.

В PR опишите цель, изменения, выполненные проверки и ограничения.
Приложите снимок экрана для видимых изменений, когда появится интерфейс.
Один из двух остальных участников проверяет PR; автор устраняет замечания.
Конфликты разрешает автор совместно с владельцем пересекающейся задачи.
Для общей ветки не используйте force push; при необходимости обновляйте её
из `origin/main` через обычный merge и повторяйте затронутые проверки.

Три участника работают в отдельных клонах/рабочих копиях. Несколько ассистентов
не должны менять один каталог одновременно, даже если планируют разные ветки.
Перед началом согласуйте владельца задачи и файлы; изменения общего API
сначала согласуйте с его потребителем. Подробные правила — в AGENTS.md.

## Проверки и секреты

Сейчас проверяются документация, локальные ссылки и `git diff --check`.
Тесты, линтеры и CI пока не настроены. После выбора стека добавьте реальные
команды установки, запуска, тестирования и сборки в этот README.

Секреты храните локально в `.env`; `.env.example` может содержать только
названия переменных и пустые/фиктивные значения. Не публикуйте ключи, пароли,
приватные сертификаты и персональные данные. `.gitignore` не защищает уже
отслеживаемые файлы — проверяйте staged diff перед каждым коммитом.
