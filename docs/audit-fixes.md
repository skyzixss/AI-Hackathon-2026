# Исправления A01–A03 из PR #17

Подготовлено отдельно от read-only аудита, на базе main 3a5130e.

- A01: подтверждённые локальные обновления useLoad применяются и к позднему
  ответу GET. Добавление заявки проверяет UUID и не дублирует запись, если
  серверный список уже включает её. Смена сессии очищает очередь.
- A02: Escape, отмена и закрытие доступны во время ожидающего RPC. Закрытие
  не отменяет серверную операцию: пользователю это объясняется. Повторная
  отправка остаётся заблокирована, поздний ответ сохраняет подтверждение
  и обновляет список счетов.
- A03: шапка, Dashboard, расписание и сроки оплаты обновляют московскую дату
  по таймеру и при возврате во вкладку. Расписание в режиме «Сегодня» следует
  новой дате, явно выбранная дата остаётся выбранной, кнопка «Сегодня» сбрасывает
  выбор к актуальному дню.

Три регрессионных теста исполняют фактические исходники через Vite/Oxc
с детерминированной моделью hooks/JSX, адаптированной из диагностического
скрипта PR #17. Проверены поздний GET, отсутствие дубля, переход московской
полуночи, явный выбор даты, закрытие зависшего RPC, запрет второго вызова
и обработка позднего успешного ответа. Это не настоящий браузер/облако.

TypeScript, 25 тестов и production build прошли. Схема/права/SQL и облачные
данные не менялись. Публичное демо не обновлено; перед выпуском требуется review другого участника.

## Браузерная проверка

На исходниках bab2de3 выполнены 11 проверок настоящего React-интерфейса
в браузере: поздний GET после успешного создания заявки; Escape и отмена
при зависшем RPC; запрет повторной отправки и обработка позднего успеха;
обновление московской даты без перезагрузки, сохранение дня, выбранного
кнопкой перехода, и возврат кнопкой «Сегодня». Дополнительно проверено
расписание при ширине 360 px.

Среда: локальный Vite и изолированный HTTP-сервер с вымышленными ответами
Supabase; часы страницы управляемые. Это проверка браузерного поведения,
не повторная проверка облачной базы или публичного сайта. Нативный календарь,
физический телефон и скринридер в этот прогон не входили.

## Исправления по review Артёма

После review c63a31f устранены две дополнительные ветки отказа:

- Подтверждённые заявки отображаются и при loading/error истории. Ошибка
  чтения остаётся видимой: локальная запись не выдаётся за полную историю.
  Поздний отказ GET не убирает уже подтверждённую запись. POST не повторяется.
- Поздний отказ оплаты показывает предупреждение после закрытия окна
  и инициирует сверку счетов. Пока окно открыто, предупреждение находится
  внутри него; после закрытия — на странице. Автоповтора RPC нет.

Добавлены проверки GET reject до/после POST, отображения заявки вместе
с ошибкой истории и позднего reject оплаты после закрытия окна со сверкой
счетов. Прошли 29 тестов, TypeScript, production build и diff-check.
Эти дополнительные проверки исполняют исходники через hooks/JSX harness;
новый браузерный или облачный прогон для отказов не выполнялся. Протокол
11 браузерных проверок выше относится к исходникам bab2de3.
