# Архитектура MVP

Решение от 04.11.2026 по поручению пользователя выбрать стек и распределить работу.
Требования: [product.md](product.md), R1–R13. Бюджет: только бесплатные тарифы.

| Область | Решение | Основание / компромисс |
| --- | --- | --- |
| Клиент | React + TypeScript + Vite | Один язык, обычный SPA; SSR для личного кабинета не нужен |
| Данные и серверный API | Supabase PostgreSQL + Data API | Постоянные данные, серверное RLS, без отдельного самодельного сервера |
| Авторизация | Supabase Auth, email/password | Хранение паролей и выдача токенов у провайдера; только два заранее подготовленных студента |
| Сайт | Cloudflare Workers Static Assets Free | Статическая сборка Vite; не требует платного серверного процесса |
| Доступ к данным | PostgreSQL RLS + минимальные GRANT | Проверка auth.uid() на сервере, а не фильтр в React |

Поток: React → Supabase Auth / HTTPS Data API → роль authenticated → RLS → PostgreSQL.
Секретный admin-ключ не нужен браузеру. Клиенту передаются только URL и publishable key;
это публичный идентификатор приложения, а не право доступа к чужим данным.
Студент не может менять профиль, оценки, расписание или статус заявки.
Уведомление о приёме заявки создаётся транзакционно серверным триггером.

создан в выбранной пользователем организации. Начальная миграция применена;
security advisor не сообщил замечаний. Облачная проверка RLS выполнена
в откатываемой транзакции. Созданы два постоянных вымышленных студента;
55 проверок Auth/REST прошли, включая выход/refresh и сохранение заявок.

Сайт опубликован в Cloudflare Workers Static Assets:
[демо «Кампус»](https://student-portal-hackathon.ankajournal-cloudflare.workers.dev).
Текущий продуктовый код main b0ed35e; версия, хеши assets и 17 проверок выпуска 05.11.2026 —
[deployment.md](deployment.md). Конфигурация `wrangler.jsonc` использует `dist/`.
Платные ресурсы не заказываем. Перед защитой проверяем доступность сервиса:
[Supabase Free](https://supabase.com/pricing) может приостанавливаться после
недели бездействия. Ограничения тарифов проверять перед размещением.

## Границы и решения

Распределение и владельцы файлов — [team-plan.md](team-plan.md).
Контракт — [api-contract.md](api-contract.md).
Пока нет кабинета сотрудника, загрузки файлов и реальной обработки деканатом.
Заявка получает `submitted`; изменение её статуса студентом запрещено.
Демо-данные только вымышленные. Публичная регистрация отключена в облаке
и локально. Email/password вход включён; пароль минимум 12 символов.

SPA использует SDK-хранилище сессии и обновление токена; UI должен очищаться
при выходе и смене аккаунта, не кешировать данные другого пользователя.
Выход отзывает refresh-сессию, но ранее выданный JWT может жить до истечения срока.
Для демо установлен короткий JWT lifetime (300 секунд); немедленная серверная
ревокация access token не заявляется и требует отдельного решения.

Дедлайн и способ подачи подтверждены [регламентом](contest-submission.md).
Открыто: оригинал задания/поля кабинета и повторная проверка доступности
бесплатного сайта непосредственно перед показом.

После настройки Auth Security Advisor сообщает одно предупреждение:
проверка утёкших паролей отключена. Она доступна только на Pro и выше
([документация](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)).
В согласованном Free-демо регистрация закрыта, два пароля случайные;
платный тариф не включался. Это ограничение демо, а не заявление о полной
готовности к работе с реальными данными.

## Демонстрационная оплата обучения

Дополнительный модуль #14 использует tuition_charges и RPC
complete_demo_tuition_payment. Общий клиент Auth не дублируется. У таблицы
включены RLS, индекс student_id/due_on и SELECT только владельцу; остальные
записи выполняет серверный RPC с проверкой auth.uid(), владельца и demo_only.
Блокировка FOR UPDATE делает повторное подтверждение идемпотентным.
Внешних запросов/реальных платежей внутри транзакции нет.

Миграция 20261104200423_tuition_demo применена только в выделенном демо-проекте
04.11.2026; подготовлены шесть вымышленных счетов A/B. Старые профили,
пароли, расписание, оценки и заявки не менялись. Прошли общий PostgreSQL-тест
и 38 live Auth/REST проверок оплаты на отдельных временных счетах.

После расширения Security Advisor сообщает два WARN. Предыдущее ограничение
leaked-password защиты Free описано выше. Второй WARN —
[authenticated SECURITY DEFINER RPC](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable).
Вызов подписанными студентами здесь намеренный: функция — узкий серверный
API демо-оплаты. search_path пустой, auth.uid()/владелец проверяются до записи,
аргумент только UUID счёта, anon/PUBLIC EXECUTE отозван. Отказ чужим,
несуществующим и анонимным вызовам проверен локально и через облачный REST.
Предупреждение не скрывалось; RPC нельзя использовать для настоящих платежей.
