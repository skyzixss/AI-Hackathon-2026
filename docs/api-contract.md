# Контракт портала v1

Контракт подготовлен по поручению пользователя; перед интеграцией участники
просматривают связанный PR. Владельцы: skyzixss — схема/SDK,
Artem545111 — UI учёбы, PUPSIK359 — UI заявок/уведомлений.
Источник типов и методов: [portal.ts](../src/api/portal.ts).

## Подключение

Создать один клиент через `createPortalClient(url, publishableKey)` из
`src/lib/supabase.ts`, затем `portalApi(client)`. React читает конфигурацию
`VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` из import.meta.env.
Никаких service_role / secret keys в VITE_ переменных.

| Метод | Результат / поведение |
| --- | --- |
| signIn(email, password) | Данные Auth; ошибка входа показывается без раскрытия существования аккаунта |
| signOut() | Выход через SDK; UI сбрасывает все данные пользователя |
| profile() | Один Profile текущего пользователя |
| schedule(from, to) | Lesson[], интервал UTC ISO 8601 [from,to), сортировка starts_at |
| grades() | Grade[], сортировка semester |
| requests() | StudentRequest[], новые первыми |
| createRequest(kind, body) | Новая StudentRequest; owner и status устанавливает сервер |
| notifications() | Notification[], новые первыми |
| markRead(id) | Обновлённая Notification; чужой/отсутствующий id даёт ошибку |

`kind`: certificate / application. `status`: submitted / in_review / ready / rejected.
`body`: от 1 до 2000 символов после обрезки пробелов. Повторная отправка
создаёт новую заявку: автоматические повторы записи не делать, кнопку блокировать
на время запроса. Отдельная идемпотентность не реализована.

Все даты — timestamptz, ISO 8601; отображение — Europe/Moscow.
Расписание сегодня/неделя переводит границы выбранных дат из этого пояса в UTC.
Идентификаторы — UUID. Nullable-поля отражены в TypeScript типах.
Расписание и оценки персональные: каждая строка привязана к student_id.

## Ошибки и доступ

SDK бросает ошибку при отказе сервера. UI различает ошибку сети, отсутствие
сессии, пустую коллекцию и отказ операции. Ошибка не превращается в успешный
результат с фиктивными данными. На все таблицы действует RLS по auth.uid().
Прямой REST-запрос чужой строки возвращает пустой набор; single() — ошибку.
Нет прав UPDATE профиля/оценок/расписания/заявок или DELETE; у notifications
разрешена только колонка read_at. Создание requests разрешено только для kind/body.
При подаче заявки триггер создаёт личное уведомление в той же транзакции.
Публичные новости пока представлены персональными демо-уведомлениями.

Минимальная проверка контракта: npm run check, npm test, npm run test:db.
Проверки прямого HTTP доступа, полного входа/выхода и реального браузера
после настройки Auth и реализации UI обязательны перед демонстрацией.
